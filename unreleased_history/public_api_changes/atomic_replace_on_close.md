Added EXPERIMENTAL `FileSystem::SupportsAtomicReplaceOnClose()` and `FileOpenContract::kAtomicReplaceOnClose`. When a `FileSystem` returns true from `SupportsAtomicReplaceOnClose()`, RocksDB writes CURRENT, IDENTITY and OPTIONS files directly under their final names with that per-open contract, without a temp file or a rename. `FileSystemWrapper` does not forward `SupportsAtomicReplaceOnClose()`, so a wrapper must override it to keep the feature.
