Added experimental `MultiScanArgs::allow_unsorted_or_overlapping_ranges`. When enabled, `DB::NewMultiScan()` accepts arbitrary bounded or unbounded range order, stages results in caller range order, and returns overlapping keys independently. Direct `Iterator::Prepare()` calls prefetch unique physical blocks for forward bounded ranges in first logical-use order and retain blocks admitted under the dispatcher memory budget through their final logical use; unadmitted, reverse, and unbounded requests use ordinary reads. External table factories must explicitly opt in through `SupportsMultiScan()`.
