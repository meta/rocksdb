Added experimental store mode: with `DBOptions::manifest_store` (see `include/rocksdb/manifest_store.h`), RocksDB keeps the MANIFEST metadata of a DB as rows in an external store. The new options `DBOptions::manifest_store_migrate` and `DBOptions::manifest_store_copy_mode` and the new function `RollBackManifestStore()` move a DB into the store and back to file mode. Secondary and follower instances, remote compaction, `DestroyDB()`, `ldb`, and checkpoints and backups of the primary instance work in store mode; a checkpoint or backup of a read-only, secondary or follower instance in store mode returns NotSupported. `DestroyDB()` of a DB in store mode needs the store in `DBOptions::manifest_store`, and also deletes leftover MANIFEST file copies. Code that copies the files of `GetLiveFilesStorageInfo()` must use `LiveFileStorageInfo::replacement_contents` for the MANIFEST. New OPTIONS files have a `manifest_row_feature_version` line.
