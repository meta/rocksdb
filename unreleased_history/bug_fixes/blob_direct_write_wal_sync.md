Fixed blob direct write values that could be lost after a power loss although their WAL record had been synced by `SyncWAL()`, `FlushWAL(true)`, a sync write, or the WAL sync before a flush. Every WAL sync now syncs the blob files first, so the blob value of each WAL record written before the WAL sync started is durable.
Fixed blob direct write with a non-default `cf_paths` or `db_paths`: blob files were written to the DB directory, so reads of those values failed with an IO error.
Fixed `Flush()` and `Close()` hanging with `paranoid_checks=false` after a blob direct write file or its directory failed to sync, or a file failed to seal; the DB now stops with a fatal background error (also for retryable errors and with `paranoid_checks=false`, so there is no automatic recovery) and must be reopened.
