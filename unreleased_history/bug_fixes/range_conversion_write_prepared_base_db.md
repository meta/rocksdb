Fixed a bug where, with `min_tombstones_for_range_conversion` set in a WritePrepared or WriteUnprepared `TransactionDB` with `two_write_queues`, an iterator opened through the base DB (for example, `GetBaseDB()`) could insert a range tombstone that permanently hid the write of a transaction whose prepare was still in progress. Read-path range tombstone conversion is now disabled for such base DB reads.
