Fixed a bug where `CreateColumnFamily()`, `CreateColumnFamilies()` or `CreateColumnFamilyWithImport()` on a secondary DB returned OK and wrote a new OPTIONS file, MANIFEST and CURRENT into the primary's DB folder. The primary kept writing to its old MANIFEST, so writes it made after that were lost when it reopened. These calls, and `DropColumnFamily()` and `DropColumnFamilies()`, now return NotSupported on a secondary or follower DB without writing any file. The bug was added in 11.13.0.
