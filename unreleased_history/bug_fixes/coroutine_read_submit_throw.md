Fixed a use-after-free in coroutine reads (`DB::GetAsync()`, `DB::MultiGetAsync()`, `CoroDB::CoGet()` and `CoroDB::CoMultiGet()`) when a file system's `FSRandomAccessFile::SubmitReadAsync()` throws after earlier requests of the same batch were submitted. The read now waits for those requests to complete before the exception propagates, instead of returning while their callbacks are still pending.
