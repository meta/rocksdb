Blob direct write now works with the WAL. During crash recovery, a WAL record whose value is in a blob file that was not flushed yet is read back from that file. If the value cannot be read (missing file, torn record or checksum mismatch), the record is handled like a corrupted WAL record and `wal_recovery_mode` decides. `kTolerateCorruptedTailRecords` fails the open, because the WAL record itself is complete and only its blob value is lost. `kPointInTimeRecovery` (the default) stops replay at that record. Read-only opens recover these values too; secondary opens do not. While a live WAL still refers to such a blob file, a checkpoint or backup without a flush returns NotSupported. Blob direct write is not supported with the WritePrepared or WriteUnprepared TransactionDB write policies, and opening such a TransactionDB with it returns NotSupported. Also fixed a bug in write groups that mix a batch rewritten by blob direct write with a batch that has protection info (`WriteOptions::protection_bytes_per_key`). In release builds, such a group could fail its writes with Corruption, or write to the WAL without checking the protection info. Debug builds failed an assertion.
