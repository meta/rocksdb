Blob direct write now supports crash recovery with the WAL on, also for read-only opens (not for secondary opens): WAL replay reads each value that is in a blob file not yet added to the MANIFEST. A value that cannot be read is handled like a corrupted WAL record, so `wal_recovery_mode` decides what happens; see `enable_blob_direct_write`. After a power loss, a write made during a concurrent `SyncWAL()` or `FlushWAL(true)` can leave a WAL record that survives while its blob value cannot be read; replay applies the corrupted-record rules. With blob direct write, the flush of a checkpoint or backup flushes all column families at one point, and the call can return `TryAgain` when a concurrent flush could make the copy fail to open; only a checkpoint or backup that flushes on a read-write DB copies every blob direct write value. Blob direct write is not supported with the WritePrepared or WriteUnprepared TransactionDB write policies.
