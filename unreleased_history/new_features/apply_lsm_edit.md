Added experimental `DB::ApplyLsmEdit()`, which atomically adds and deletes SST files at caller-declared levels across column families. Range replacement preserves DB-generated sequence numbers and probes retained straddling files for entries or tombstones affecting the range. When every replacement file supports external SST V2 global sequences and contains only sequence-zero entries, fresh sequences and a covering tombstone can replace a nonempty range without rewriting its straddling files. Optional upward relocation makes room for that tombstone; exact declared levels remain the default.

`LsmEditOptions::merge_incoming_files` optionally compacts incoming files into one SST per declared level before atomic installation. Existing destination SSTs are never included in the merge. This permits overlapping incoming files at a nonzero level, but does not permit overlap with a surviving destination file at that same level. Higher entry sequences win; later input files resolve equal-sequence point overwrites. Normal merge operands and range tombstones are preserved. Outputs use destination table/compression options, without running its application compaction filter.

For a snapshot constructed in another DB, `LsmEditFile::zero_sequence_numbers` discards that input's DB-local point sequences during merging. Reset inputs must contain snapshot points, not merge operands or range tombstones. Later non-reset online-event inputs retain their destination-DB sequences and supersede the snapshot. The destination sequence watermark advances for non-reset inputs only.

Merging rewrites incoming data once, opens one reader per input, and takes approximately O(K log F) work per level for K input entries across F files. It avoids incoming-file pairwise sequence validation within a merged level; validation still applies between outputs and surviving destination files. Overlap scans seek to the common key range rather than scanning unrelated prefixes. This opt-in mode trades installation I/O for a compact incoming run; it is not a metadata-only graft. Its read/write bytes are included in compaction counters.

Active snapshots are rejected by default. Add-only explicit edits may set `snapshot_consistency=false` when importing a keyspace that old snapshots cannot read, or when the caller accepts snapshot-inconsistent visibility of imported data. Bounded range edits may also opt out with incoming merging and straddler probing enabled, but fail if any destination file would be deleted or a straddler contains point entries or range tombstones in the range. The opt-out cannot delete destination data.

When merging an opted-out add-only edit, RocksDB uses its normal compaction snapshot context to retain imported versions needed by snapshots already active during preparation. This does not make importing old or foreign sequences snapshot-consistent, but avoids discarding incoming history needed by those readers.
