Added new DB options `use_blog_format_for_wals`, `use_blog_format_for_blobs`, `blog_checksum`, and `blog_timestamp_size` to enable the new "blog" file format for WAL and blob files. The blog format uses escape-sequence record framing with context checksums. Existing legacy format files remain readable regardless of these settings. DB option `blog_wal_streaming_compression` compresses blog WAL records as one ZSTD stream per file instead of record by record. Enabling `use_blog_format_for_wals` is not downgrade-safe: releases without blog WAL support can silently lose the unflushed writes in blog-format WALs. With `paranoid_checks=false`, recovery of a blog WAL follows `wal_recovery_mode` and stops reading that WAL at the first corrupted record, while later WALs are still replayed; legacy WALs skip the corrupted record and continue. Use `kSkipAnyCorruptedRecords` to recover records past the corruption.
