Added `DBOptions::partition_wal_usage`. When set to a value other than `kNone`, each WAL record is tagged with an ordering number (wal_index) that is persisted on disk. The default `kNone` keeps the WAL bit-for-bit compatible with the previous format for downgrade safety. Indexed WALs are intentionally fail-closed: older RocksDB versions report them as corruption rather than reading them. To roll back, set `partition_wal_usage` to `kNone`, flush every column family so indexed WALs become obsolete, wait for those WAL files to be deleted, and only then downgrade the binary.
