`DBOptions::read_io_executor_threads` now defaults to 0, so opening a DB or `SstFileReader` no longer starts async read threads or io_uring event loops for applications that do not use async reads. `DB::GetAsync()`, `DB::MultiGetAsync()`, `CoroDB::CoGet()` and `CoroDB::CoMultiGet()` now fall back to synchronous reads unless `read_io_executor_threads` is set to a positive value, by this or another DB or `SstFileReader` in the process.
