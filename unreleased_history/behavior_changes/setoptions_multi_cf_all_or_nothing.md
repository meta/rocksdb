`DB::SetOptions()` for several column families is now all-or-nothing: if the options for any of them are invalid, or any of them is dropped, no column family's options change. Before, the column families handled before the failing one kept their new options. One exception: an option that changes a shared object in place, such as `table_factory.filter_policy.bloom_before_level` or a field of a custom `merge_operator`, takes effect when the call parses it, for every column family that shares the object, and a failed call does not undo it.
