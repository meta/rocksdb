The experimental trie index (`TrieIndexFactory`) has a new on-disk format that is smaller, faster to search and supports data blocks past 4 GiB. Trie blocks from earlier releases fail with `NotSupported`: in `kStandardDefault` their SSTs fall back to the standard index, so compact there to rewrite them. SSTs written in `kCustomOnly` have no standard index, so rewrite them in another mode before upgrading. Earlier releases cannot read the new trie blocks. The empty user key no longer fails flushes and compactions as a trie separator, and `DB::Open()` and `CreateColumnFamily()` now reject the trie with a non-bytewise comparator outside `kStandardOnly`.
